SIGNALING BROKER GUIDE

Self-hosted PeerJS signaling for AOW3 lockstep multiplayer — and why HTTPS pages need WSS (TLS).

1 · What the broker does (and does not do)

AOW3 multiplayer is pure peer-to-peer: once a match is live, every command, input frame and state hash flows directly between the browsers over a WebRTC DataChannel. The signaling broker is only used while finding each other — it matches the room code to the peers' WebRTC connection offers and answers. If the broker goes down mid-match, the match continues; the broker is needed again only for new joins (JIP / late spectators).

By default the game uses the free public PeerJS cloud (0.peerjs.com). You can leave that dependency by running your own broker and entering its address in the optional broker field of the multiplayer panel.

2 · The HTTPS rule — why WSS

The game is hosted on GitHub Pages over HTTPS. A page opened over HTTPS is only allowed to open secure WebSocket connections. If the page at https://… tries to signal with a plaintext ws:// broker, the browser blocks it as mixed content and the console shows:

Mixed Content: The page at 'https://…' was loaded over HTTPS,
but requested an insecure WebSocket endpoint 'ws://…'. This request has been blocked.
So: on an HTTPS page (GitHub Pages, any HTTPS mirror) your broker must terminate TLS and be reachable as wss://. Plain ws:// works only from an HTTP page — e.g. http://localhost tests.

3 · Quick start — same machine / HTTP pages

# any machine with Node.js 18+
npx peer --port 9000

Then enter localhost:9000 in the broker field. This plaintext path is fine for local testing from an http:// origin — it is exactly what the browser blocks from an HTTPS origin.

4 · Production — WSS behind a TLS proxy

The peer package (PeerServer) does not speak TLS itself. The standard setup is to keep it on localhost and let a reverse proxy own the certificate. WebSocket upgrades are proxied transparently by both options below.

Option A — Caddy (automatic HTTPS, recommended)

# /etc/caddy/Caddyfile
broker.example.com {
    reverse_proxy 127.0.0.1:9000
}
sudo systemctl reload caddy   # certificates are issued automatically

Caddy obtains and renews the Let's Encrypt certificate on its own — no certbot, no manual websocket configuration. Enter broker.example.com in the game.

Option B — nginx + certbot

server {
    listen 443 ssl;
    server_name broker.example.com;
    # ssl_certificate /etc/letsencrypt/live/broker.example.com/fullchain.pem;
    # ssl_certificate_key /etc/letsencrypt/live/broker.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:9000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 300s;
    }
}
sudo certbot --nginx -d broker.example.com
sudo systemctl reload nginx

Broker flags

npx peer --port 9000               # default path /
npx peer --port 9000 --path /myws  # custom path (then enter broker.example.com/myws)
npx peer --port 9000 --key mykey   # custom REST key (rarely needed)

5 · What to enter in the game

Broker fieldResulting connectionUse
(empty)public PeerJS cloud (0.peerjs.com)zero-setup default
localhost:9000ws://localhost:9000/local tests from an HTTP page
broker.example.comwss://broker.example.com:443/ (inferred from the HTTPS page)typical production entry
wss://broker.example.comwss://…:443/ (explicit scheme always wins)unambiguous, works from HTTP pages too
wss://broker.example.com:8443explicit secure portproxy on a non-443 port
wss://broker.example.com/mywscustom pathserver run with --path /myws
ws://10.0.0.2:9000forced plaintextHTTP pages / LAN only

Parsing rules: an explicit wss:///ws:///https:///http:// prefix decides the security mode; without a scheme, an HTTPS page infers wss on port 443 — unless you typed an explicit port, which keeps plaintext (typo-proof against a host:port habit). The path defaults to /.

6 · Troubleshooting

SymptomCause / fix
Console: Mixed Content … blockedHTTPS page → plaintext broker. Terminate TLS (Caddy/nginx) and enter wss://… or the bare domain.
Certificate warning / peer-errorThe browser must trust the certificate before WebRTC will connect. Use a real CA cert (Let's Encrypt) or mkcert for localhost.
Joins time out, broker logs show nothingPath mismatch — --path /myws on the server must match the path you enter. Also check the proxy forwards WebSocket Upgrade headers.
Still reaching the public cloudThe broker field is read when the room is created — press HOST again after changing it.
Match continues but new joins failExpected — the broker is only needed to find peers. Restart the broker for JIP/spectators.
Port already in useAnother process owns 9000 — pick another port and enter host:port.

7 · Notes

  • Signaling only — game traffic stays P2P; STUN/ICE defaults (PeerJS default STUN) are unchanged by self-hosting the broker.
  • The room code derives the PeerJS peer id (AOW3LS-<code>); the host id registers on your broker, guests connect to it through your broker, then everything is direct.
  • Game version and broker choice are independent — a v-mismatch is still rejected by the PROTO handshake, not by the broker.
